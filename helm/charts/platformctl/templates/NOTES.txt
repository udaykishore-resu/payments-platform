If the migration Job failed:

  kubectl -n {{ .Release.Namespace }} logs job/{{ include "pp-common.fullname" . }}-migrate

The sync failed, so the new pods never started and the previous version is still
serving. Do NOT re-run it blindly and do NOT run `migrate down` — production
rollback is forward-only, with a new, higher-numbered compensating migration
(deployment.md §5.4). Down migrations exist for local resets and for CI to test
both directions; running one on production data during an incident is the
highest-risk action available.

An `--expect-version` mismatch means a migration was skipped or re-ordered. Fix
the release manifest, not the database.
